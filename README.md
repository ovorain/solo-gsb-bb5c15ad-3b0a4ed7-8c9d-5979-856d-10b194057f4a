# 折页阅读顺序校样 Web 应用

在行列纸格上标注正反面页码，逐步添加“沿某条网格线向左 / 右 / 上 / 下折叠”的步骤，
系统模拟面片翻转、上下层级与页码朝向，支持任意一步回放，并在全部折叠完成后输出
**从封面到封底的页码阅读顺序**。

当出现下列两种印张折手中的典型错误时，系统会**拒绝执行该步并在画布上标出冲突纸格**：

- **折线不在当前外轮廓上（contour）**：移动纸瓣镜像后越过纸块边缘形成悬空；
- **两侧厚度不一致（thickness）**：折线两边叠层厚度不等（包折 / 不等厚折法）。

全部折叠完成后还可运行**生产质量审计**：按印刷交付规则检查空白 / 重复页码、
最终分离叠层、倒置页码、未覆盖纸格与折叠后容量异常，逐条给出严重级别、
对应原始纸格与可读说明，汇总“可发布 / 需修订”结论，并可导出 JSON 报告。

技术栈：Node.js + Express（服务端），原生 HTML / CSS / Canvas（前端），
折叠模拟为一份零依赖的纯逻辑引擎，浏览器与服务端共用同一份代码。

> **书帖爬移补偿**（新增）：收成单叠后输入纸张厚度与可用出血，按
> “补偿量 = 纸厚 × 外侧叶数”逐叶计算前口→书脊的内移量，并换算为
> 原始纸格正/反面的带符号横向偏移；超出血的面标红禁用，应用后参数与
> 逐面偏移写入方案的独立字段 `creepCompensation`（保存/导入/服务端载入均保留）。

> **标签 / 备注 / 列表筛选**（新增）：保存方案时可维护 **0～8 个标签**与一条
> **备注（≤500 字符）**，服务端对标签做 trim、折叠连续空白与**去重**后随方案持久化；
> “已存方案…”列表支持按**标签交集**、**名称关键词**与**最近更新时间**（1 / 7 / 30 天）
> 组合筛选，返回更新时间倒序（同时间按 id 升序）的**稳定排序**与**匹配计数**。
> 非法标签（空、非字符串、含 `, ; |` 或控制字符、超长、超量）或过长名称 / 备注
> 会被**整请求拒绝（HTTP 400）且不改动任何旧存档**。

> **校样批注**（新增）：可在**任一回放步骤**为**原始纸格的正 / 反面**添加带
> **严重级别**（严重 / 警告 / 建议）的文字批注；批注始终绑定**原始面片身份**
> （`cell`+`face`），切换回放步、截断 / 重排折叠步骤后仍经引擎重放到正确格位，
> 画布格顶以**正 / 反两枚色点**聚合显示该叠内全部批注（颜色=未解决的最高级别，
> 全解决为绿勾，数字为条数）。支持**仅未解决**及级别 / 面别组合筛选、
> **解决 / 恢复**（编辑已解决批注的正文或级别会自动恢复为未解决）、
> 随方案**保存 / 导出 / 导入**（保存严格校验整请求拒绝，导入宽容规整逐条丢弃坏数据），
> 并可通过只读接口 `POST /api/annotations/locate` 脚本化定位。

> **版本差异审阅**（新增）：服务端对**每次成功保存**保留一份**不可变方案快照**
> （`<id>.versions/v000006.json`，只追加、永不原地改写）。右侧“版本差异审阅”卡片可
> 选择同一方案的**两个版本**比较：以**原始纸格**与**步骤序号**为稳定身份，列出
> 正/反页码、折叠步骤、标签/备注、校样批注与爬移补偿的**增 / 删 / 改**，并在画布以
> **紫色描边高亮全部受影响纸格**（夹在叠中时按层偏移描边）；点差异行的
> “在 vN 查看”即载入该版本进入**只读审阅**并联动回放到对应步骤/纸格/批注。
> 可把任一历史版本**恢复为当前草稿**（恢复前确认；历史快照不覆盖、不删除，
> 下次保存另起新版本并标记 `reason:"restore"` 与来源版本），恢复后继续沿用现有
> 回放、审计与保存流程。审阅模式下全部编辑控件锁定，回放 / 轨迹 / 审计 / 双面版预览
> 等只读能力照常使用。

## 一条命令启动

```bash
docker compose up --build -d
```

启动后在浏览器打开：

> **http://localhost:3000**

停止：

```bash
docker compose down
```

> 不使用容器时（本机已装 Node.js ≥ 18）也可以：
> `npm install && npm start`，然后访问同一地址。

方案 JSON 保存在容器内 `/app/data`（Compose 已声明命名卷 `fold-data`，删除容器不丢方案）。

## 使用说明

1. **创建行列纸格**：左侧输入行数、列数（1–12），点击“创建网格”。
2. **标注页码**：点击画布中的任一纸格，在弹层中分别填写该片叶子的
   **正面页码** 与 **反面页码**（留空表示空白页）。
3. **添加折叠步骤**：
   - 在左侧选择竖直线（左右折）或水平线（上下折）及位置，再点四个折叠按钮；
   - 或者直接点击画布边缘的折叠手柄（▲▼◀▶）。
   - 方向含义：**“向左折”= 折线右侧的纸瓣向左翻过折线并落下**，其余同理。
   - 非法手柄显示为红色虚线；点击非法折法时不会执行，并在下方给出原因、
     在画布上用红底标出冲突纸格。
4. **逐步回放**：用顶部的 ⏮ / ◀ / ▶播放 / ▶| 按钮或进度条，查看任一步后的
   面片位置、叠层厚度（`×N`）、朝上的是正面还是反面、以及页码是否倒置（`⟲倒`）。
5. **面片轨迹**：右侧“面片轨迹”卡片中选择某个**原始纸格**及其**正/反面**：
   - 系统从**第 0 步到末步**生成时间线，每个节点列出该面片当前**所在格位**、
     在叠层中的**层序**（`层 2/4` = 4 层叠中自上而下第 2 层）、所选面
     **朝上/朝下**与**正立/倒置**，以及该面页码；
   - 轨迹始终以**原始面片身份**跨折叠追踪（叠层合并、瓣内倒序后仍准确），
     **点击任一节点**即联动顶部回放定位到该步，并在画布中用橙色描边与
     `轨 层/总层` 徽标高亮该片（夹在叠层中间时高亮随层序偏移显示）；
   - 遇到**首个非法步骤**时时间线在该处中断：此前节点全部保留，
     末尾红色“中断”节点标明原因（外轮廓 / 厚度不一致）与冲突纸格，
     点击中断节点定位到中断前最后一步；
   - 网格、标注或步骤变化后时间线**自动重算**；追踪选择不写入方案，
     保存与导入格式不变。
6. **阅读顺序**：右侧“最终阅读顺序”按骑马钉式折帖叶序输出
   封面 → … → 封底的页码序列；倒置页码以红底标出，空白页显示“空白”。
   尚未收成单叠时，会分组列出每个分离叠层的序列。
7. **生产质量审计**：右侧“生产质量审计”卡片对方案**完整重放全部步骤**
   （与回放停在第几步无关）后按印刷交付规则自动检查，结果只读、不改动方案：
   - 检查项与严重级别：**重复页码**（错误）、**最终分离叠层**（错误）、
     **倒置页码**（错误，含未标注的空白倒置槽，文案不虚构页码）、
     **折叠后容量异常**（容量守恒校验为错误；
     单叠总页数非 4 的倍数为警告）、**空白页码**（警告）、
     **未覆盖纸格**（正反面皆空，警告）；
   - 每条结果给出严重级别、对应**原始纸格**与可读说明（含阅读序列槽位），
     卡片顶部汇总“✓ 可发布 / ✗ 需修订”结论（存在错误级结果即需修订）；
   - 方案含**非法折叠**时审计中止，仅报告首个错误（步骤号、原因与冲突纸格），
     不伪造后续检查结论；修正后自动重新审计；
   - “导出 JSON 报告”把方案与审计结果（结论、统计、逐条结果）保存为本地 JSON；
   - 网格、标注或步骤变化后审计自动重算。
8. **自动拼版**：仅当**全部折叠步骤都可合法回放且已收成单叠**时，
   右侧“自动拼版”卡片才允许输入**起始页码**与**成品页数**：
   - 系统按最终封面→封底的阅读槽位依次写入连续页码，再反向映射到
     每个原始纸格的正/反面；
   - 成品页数小于纸格总面数（`行数×列数×2`）时，序列末尾的剩余槽位
     留空白，预览表中逐行标明空白槽位所属的原始纸格与面；
   - “生成预览”**不会改动当前标注**；确认后才批量写入；若现有标注非空，
     确认前会汇总所有将被覆盖/清空的位置（写入前还会二次确认）；
   - 非法折叠、未收成单叠或页数超出容量时，生成按钮禁用并给出具体原因。
9. **折手自动寻路**：右侧“折手自动寻路”卡片中，指定某个**原始纸格**的
   **正面或反面**作为最终朝上的封面，点击“搜索最短折法”：
   - 搜索从**当前方案全部步骤合法回放后的末态**出发（与回放停在第几步无关），
     枚举引擎当前允许的折线与方向，按 BFS 求“收成单叠且封面符合指定”的
     **最短**后续步骤；
   - 命中后最多展示 **3 条等长最短方案**，逐条列出每一步的折线与方向；
     点击某方案的“**追加到当前步骤并回放**”，即把该方案的步骤追加到当前方案末尾，
     并进入既有回放（自动定位到末态），随后可继续编辑、保存或自动拼版；
   - 状态键完整包含各格**叠层顺序、面片朝向与相对位置**，不会把终态不同的
     状态误合并；
   - **仅支持不超过 4×4 的网格**，搜索以**最多 8 个后续步骤、2 秒**为上限：
     限步内可达状态全部穷尽仍未命中时提示“**无解**”；
     达到时间上限仍未确认时提示“**搜索超限**”；
   - 当前方案含非法折叠、或网格超过 4×4 时，搜索按钮禁用并给出原因；
     搜索本身不改动当前步骤，只有手动“追加”才会写入。
10. **双面印刷版预览**：右侧“双面印刷版预览”卡片中选择翻面方式，点击“生成双面版预览”：
   - **长边翻转**（沿纸张竖边左右翻面，常规骑马钉/侧边装订）或
     **短边翻转**（沿纸张横边上下翻面，tumble/台历式翻页）；
   - 系统并排生成**正面版（第 1 印刷面）与背面版（第 2 印刷面）**：
     正面版纸格按原始行列排列；背面版纸格按所选翻转边**镜像**
     （长边=左右镜像，短边=上下镜像），格内页码再依据该面片在折叠末态的
     朝向（`frame.y`）做 **180° 倒置补偿旋转**——打印后沿所选边翻面、再按
     既有步骤折叠时，所有页码正立出现，阅读顺序与当前回放一致；
   - 每个纸格标出**原始纸格坐标**（列,行，0 基）、**面别**（正面/反面）、
     **页码**与**旋转方向**（`0° 不转` / `⟲ 旋转 180°`，仅字形旋转），
     空白面以斜纹底纹保留“空白面（占位）”；版头下方彩条标出翻面装订边；
   - 预览为只读，不改写当前标注；方案被改动时预览即时重算，变得非法或
     不再是单叠时自动关闭；
   - **非法折叠、尚未收成单叠或未创建网格时按钮禁用**，下方红字说明具体原因。
   - **打印设置**：预览覆盖层中点“**打印 / 另存 PDF**”（或浏览器 `Ctrl/Cmd+P`）：
     - 目标：实际双面打印机选“**双面打印 / 双面沿长边翻页**”或
       “**双面沿短边翻页（翻转）**”，须与卡片中选择的翻面方式一致；
       无双面打印机时先打印正面版，再按提示的翻面边手工翻纸打印背面版；
     - 缩放：**100%（实际大小）**，关闭“适应页面边框”外的额外缩放，
       纸张 A4（或与纸格比例相近的横向纸）；
     - 应用已内置打印样式：**自动隐藏全部编辑控件，正面版、背面版各占一页**
       （A4 横版），无需在打印对话框中再做隐藏设置。
11. **书帖爬移补偿**：右侧“书帖爬移补偿”卡片在**全部折叠步骤合法且收成单叠**后可用：
    - 输入**纸张厚度**与**可用出血**（同单位，如 mm）；系统以**最外叶（封面叶）
      为第 0 层**，某叶补偿量 = 纸厚 × 其外侧叶数，沿该页**前口 → 书脊**方向
      移动内容，再依据面片末态朝向换算为**原始纸格正/反面的带符号横向偏移**
      （反面按长边翻面排版惯例左右镜像，正/反符号相反；横折脊时承载轴为纵向、正反相同）；
    - 书脊由**最后一步折叠**的折线确定（末折即装订脊折），卡片给出书脊位置、
      **逐叶明细表**（层序、原始纸格、外侧叶数、补偿量、正/反面偏移）与**最大补偿**
      （纸厚 × (叶数−1)，最内叶）；
    - 任一面偏移**绝对值超过可用出血**时，该原始纸格对应面在表中**标红**并
      **禁用“应用补偿”**（等于出血为界内，纸厚 0 或出血 0 都可正常计算）；
    - 点击“应用补偿”后，参数与**逐面偏移**写入方案的**独立方案字段
      `creepCompensation`**（含参数、书脊、最大补偿、逐格逐面偏移与几何基线签名），
      **保存到服务器、导出/导入 JSON、服务端载入均原样保留**；“清除已应用”删除该字段；
    - 网格、折叠步骤或参数变化后明细**自动重算**；已应用方案与当前几何/参数
      不一致时保留字段并**标黄提示需重新应用**，不会静默改写；
    - 方案含**非法折叠**或**尚未收成单叠**时卡片禁用并说明原因（未折叠的 1×1
      单叠可计算，补偿全为 0）。
12. **校样批注**：右侧“校样批注”卡片与画布标记配合使用：
    - **添加**：先用顶部回放条停在任一步，再点击画布中的格位（折叠后格内为一个叠，
      弹层会逐片列出每个**原始纸格**），在弹层中点该片的
      **“＋ 正面批注 / ＋ 反面批注”**，选择严重级别（**严重 / 警告 / 建议**）、
      填写正文（≤500 字符）后保存；批注记录添加时的回放步，但**身份键是原始纸格 + 面别**；
    - **身份定位**：批注不绑定当前屏幕格位，而是绑定原始面片。切换回放步、
      删除后半段步骤、重排或追加折叠后，系统按引擎重放重新计算该片的
      **当前格位、叠内层序与正/反面朝向**并移动标记——同一条批注永远落在同一片纸上；
    - **画布标记**：每个被批注面片所在的格顶出现两枚圆点（左=正面、右=反面），
      颜色取该面**未解决**批注的最高严重级别（红=严重、橙=警告、青=建议），
      全部解决为带勾绿点；圆点上显示该面批注条数；在批注列表点
      **“定位到面片”**会跳回该批注创建步并用青色虚线框高亮该片所在格；
    - **筛选**：卡片顶部可勾选**仅未解决**，并按**严重级别**与**正面 / 反面**组合筛选；
      统计行显示总数、各级别未解决数与已解决数，回放在非法步截断时标注“按截断前状态定位”；
    - **解决 / 恢复**：每条批注可“标记已解决”（记录解决时间、列表划线置灰、画布变绿勾），
      也可“恢复为未解决”；**编辑已解决批注的正文或级别会自动恢复为未解决**；
    - **保存 / 导入导出**：批注随方案整体保存到服务器、写入导出 JSON、随导入载入；
      保存走与标签相同的严格校验（坏批注整请求 400 拒绝、不改旧档），
      导入走宽容规整（坏条目逐条丢弃、级别非法降级为建议、正文超长截断）；
      “导出 JSON 报告”（审计）同样附带全部批注与批注统计；
    - 非法折叠回放截断时，批注仍按截断前最后合法状态定位，不会丢失或错位。
13. **保存 / 载入**：
   - “保存到服务器”将方案 JSON 存入容器数据卷，可通过“已存方案…”再次载入；
   - “导出 JSON / 导入 JSON”在本地文件与应用之间交换方案；
   - **标签（0～8 个）**：在存取卡片的标签框输入后回车或点“添加”，每个标签
     ≤20 字符；点标签上的 `×` 删除单个、点“清除全部标签”清空。保存时服务端会
     去除首尾空白、折叠连续空白并按规范化结果**去重**（保持首次出现顺序）；
   - **备注（≤500 字符）**：直接在备注框填写，随方案保存/导出；
   - **列表筛选**：点“已存方案…”展开筛选条，可组合使用
     **标签交集**（逗号或分号分隔，须全部命中，如 `骑马钉,A4`）、
     **名称关键词**（大小写不敏感）与**最近更新时间**（1 / 7 / 30 天）；
     列表每条显示名称、规格、标签（点击标签即可追加为筛选条件）、备注摘要与更新时间，
     顶部提示“筛选命中 N / 总数 M 个存档”；点“清除筛选”恢复全部存档；
   - 非法标签 / 过长输入在前端与服务端**双重拦截**：保存被整请求拒绝，
     服务器上的旧存档**保持不变**（更新时间也不会变化）。
14. **版本差异审阅**：右侧“版本差异审阅”卡片在方案保存到服务器后可用：
    - **不可变快照**：每次点“保存到服务器”成功，服务端都会把本次方案完整写入
      一个只追加的版本文件（v1、v2、…）；之后无论怎样修改、再次保存，旧版本文件
      都不会被改动。删除方案时才会连带删除全部历史版本。
    - **比较两个版本**：在“版本 A（旧）/ 版本 B（新）”下拉中选择同一方案的两个
      版本（保存后默认选中最近两个），点“比较版本”。系统以
      **原始纸格坐标 + 面别**（页码）、**步骤序号**（折叠步骤）、**批注 id** 为稳定
      身份，分段列出：网格尺寸、标签/备注/名称、折叠步骤、正/反页码、校样批注、
      爬移补偿的**新增 / 删除 / 修改**，并给出每项的旧值 → 新值与受影响原始纸格；
      顶部汇总各类条数与受影响纸格总数。纯标签顺序调整不报差异；版本之一含非法折叠时
      几何比对按截断态进行并提示。
    - **画布高亮**：比较后画布以**紫色虚线描边**标出所有受影响原始纸格（折叠改动的
      移动瓣、页码/批注所在格、以及末态位置/层序/朝向发生变化的纸格）；点击差异聚焦时
      对应纸格改为**加粗实色紫框**。右侧折叠步骤列表中差异步骤标注“增 / 删 / 改”。
    - **联动回放**：每条差异提供“在 vA 查看 / 在 vB 查看”按钮（新增项仅新版本可看、
      删除项仅旧版本可看）。点击后载入该版本进入**只读审阅**，自动定位：折叠步骤跳到
      对应步骤序号；页码差异跳到末态并高亮该原格；批注差异跳到批注创建步并选中该批注。
      审阅模式顶部显示紫色横幅，画布上可继续点击纸格反查差异；顶部回放条、面片轨迹、
      生产质量审计、双面印刷版预览等只读功能照常工作，全部编辑入口锁定。
    - **恢复历史版本**：审阅横幅中点“恢复为当前草稿…”，确认后该历史版本内容成为
      **当前草稿**并退出版阅：**历史快照不覆盖、不删除**；“返回当前草稿”则放弃查看、
      还原进入审阅前的草稿。恢复得到的草稿沿用现有保存流程——下一次“保存到服务器”
      会**追加一个新版本**（版本列表中标注“恢复自 vN”），随后可继续重放、审计与编辑。
    - 审阅中的历史版本不能直接保存/导出/编辑；导入 JSON、新建网格、删除存档等操作
      在审阅期间也会被拦截，避免误改。

### 方案 JSON 格式

```json
{
  "name": "8页折帖",
  "rows": 2,
  "cols": 2,
  "labels": {
    "0,0": { "front": "4", "back": "5" }
  },
  "steps": [
    { "axis": "v", "line": 1, "dir": "r" },
    { "axis": "h", "line": 1, "dir": "d" }
  ],
  "tags": ["骑马钉", "A4", "待复核"],
  "note": "首件已确认，纸厚 157g。",
  "annotations": [
    {
      "id": "a1m8x0k2q7tz",
      "cell": "0,0",
      "face": "front",
      "severity": "error",
      "text": "封面套印偏差，需重新制版",
      "step": 1,
      "resolved": false,
      "createdAt": "2026-09-22T04:00:00.000Z"
    }
  ],
  "createdAt": "2026-09-22T01:00:00.000Z",
  "updatedAt": "2026-09-22T03:20:00.000Z"
}
```

- `labels` 的键为 `列,行`（0 基），值为该格正反面页码字符串；
- 步骤中 `axis`：`v` 竖直线 / `h` 水平线；
- `line=k` 表示第 `k-1` 与第 `k` 列（或行）之间的网格线（`1 ≤ k < 列/行数`）；
- `dir` 为纸瓣落向：竖线用 `l` / `r`，横线用 `u` / `d`；
- `tags`：0～8 个标签，服务端逐项 trim、折叠空白后去重，单个 ≤20 字符，
  不含控制字符与 `, ; |`（导入旧 JSON 时坏标签会被宽容过滤，不影响方案载入）；
- `note`：备注字符串，trim 后 ≤500 字符；
- `annotations`：0～200 条校样批注（无批注时为空数组），每条：
  - `id`：客户端生成的唯一 id（字母/数字/`_`/`-`，6～32 字符；保存时缺失自动补）；
  - `cell`：**原始纸格**坐标 `"列,行"`（0 基），必须在当前网格内——批注随面片身份定位；
  - `face`：`front` 正面 / `back` 反面；`severity`：`error` 严重 / `warning` 警告 / `info` 建议；
  - `text`：正文，trim 后 1～500 Unicode 码点，允许制表符与换行，不允许其它控制字符；
  - `step`：批注创建时所在回放步，`0..steps.length` 的整数（仅作信息与“定位回该步”，
    不影响定位计算——任何步都按面片当前实际位置重算）；
  - `resolved` / `resolvedAt`：是否已解决及解决时间（ISO）；`createdAt`：创建时间；
  - 保存时任一条非法即**整请求 400 拒绝**（错误码 `bad_annotations` /
    `bad_annotation` / `bad_annotation_id` / `duplicate_annotation_id` /
    `bad_annotation_cell` / `bad_annotation_face` / `bad_annotation_severity` /
    `bad_annotation_text` / `annotation_too_long` / `annotation_control_chars` /
    `bad_annotation_step` / `bad_annotation_resolved` / `too_many_annotations`）；
    导入时则宽容规整：坏条目丢弃、级别非法降级为 `info`、超长截断、越界 step 钳制。
- `createdAt` / `updatedAt`：ISO 时间戳，更新方案时 `createdAt` 保留、
  `updatedAt` 刷新；缺少这些字段的旧存档在列表中以空标签/空备注、文件 mtime 兼容呈现。

应用过爬移补偿的方案还会带独立字段 `creepCompensation`（不应用则缺省）：

```json
{
  "params": { "paperThickness": 0.1, "bleed": 3 },
  "spineAxis": "vertical",
  "spineSide": "left",
  "maxCompensation": 0.3,
  "faces": {
    "0,0": { "front": 0, "back": 0, "axis": "x", "creep": 0 },
    "1,0": { "front": -0.1, "back": 0.1, "axis": "x", "creep": 0.1 }
  },
  "basis": { "rows": 1, "cols": 2, "stepsSignature": "…" },
  "appliedAt": "2026-09-22T00:00:00.000Z"
}
```

- `faces` 以原始纸格为键，给出该格正/反面在各自印版视图中的带符号横向偏移
  （正数=面向右/下移，负数=向左/上移）、承载轴 `axis`（`x` 横 / `y` 纵）与该叶补偿量；
- `basis.stepsSignature` 为应用时的网格+折叠步骤签名，载入后用于识别方案是否已过期；
- 载入时该字段仅做结构规整（非法静默丢弃），不影响方案其余部分。

### 不可变版本快照存储格式

每次成功保存（`POST /api/plans`）后，服务端在数据卷追加一个版本快照
`DATA_DIR/<id>.versions/v000006.json`（6 位零填序号，从 v1 起，临时文件 + rename 原子写入）：

```json
{
  "version": 6,
  "planId": "ab12cd34ef56",
  "reason": "save",
  "restoredFromVersion": null,
  "savedAt": "2026-09-22T05:10:00.000Z",
  "plan": { "name": "8页折帖", "rows": 2, "cols": 2, "…": "当时保存的完整方案 JSON" }
}
```

- 快照**只追加、永不原地改写**：再次保存只新增更高序号文件；`reason` 为 `restore` 时
  带 `restoredFromVersion`（恢复来源版本号）。
- 快照文件不会被 `GET /api/plans` 列表扫描（仅识别 DATA_DIR 顶层 `*.json`）；
  方案文件删除时其 `<id>.versions/` 目录一并删除。
- 快照中的 `plan` 与方案文件格式一致，`GET /api/plans/:id/versions/:version`
  原样返回；浏览器端的差异计算（`FoldEngine.diffPlans`）与服务端
  `GET /api/plans/:id/diff` 使用同一份共用引擎代码。

## 折叠模型

- 每个面片持有 3 个单位方向向量（右 `x`、下 `y`、正面法线 `n`）；
  竖直 180° 翻折令 `x, n` 反向，水平翻折令 `y, n` 反向，由此得到：
  - 每片叶子朝上的是正面还是反面（`n` 的 z 分量）；
  - 页码正立还是倒置 180°（`y` 的 y 分量）。
- 移动叠翻面后内部倒序，再整体压到静止叠之上，得到真实的上下层级。
- 校验规则：
  - **外轮廓**：每个移动格镜像后的落点必须已被占用（压到静止瓣或与瓣内另一格配对），
    否则该格及其悬空落点被标为冲突；
  - **厚度**：移动格压到静止格位时双方层数必须相等，否则两侧格位都被标为冲突。

## 运行测试

```bash
npm test                 # node --test：引擎 / 拼版 / 寻路 / 轨迹 / HTTP 测试
node tests/ui-smoke.js   # 前端主流程冒烟（DOM 桩，独立运行）
```

服务端另有 `POST /api/simulate`（body 同方案 JSON，可用 `upto` 指定回放步数）返回
叠层、面片朝向与阅读顺序，便于脚本化校验折手方案。

`POST /api/impose` 在方案 JSON 之外附加 `startPage`、`pageCount`，返回自动拼版结果：
`labels`（写回每个原始纸格正/反面的连续页码，两面皆空者省略）、
`slots`（逐槽位的页码、空白标记、`origin` 原始纸格、`face` 面别、`upright` 朝向）、
`capacity`、`blankTrailing` 以及 `overwrites`（将被覆盖的现有非空标注）。
前置条件不满足时返回 `ok:false` 与具体错误码
（`contour` / `thickness` / `not_single_stack` / `too_many_pages` / `bad_start` / `bad_count`）。
自动生成的标签就是普通 `labels`，保存、导入导出与 `/api/simulate` 回放均原样保留。

`POST /api/duplex-plate` 在方案 JSON 之外附加 `flip`（`long` 长边翻转 / `short` 短边翻转），
返回双面印刷版数据：`front` / `back` 两版各含 `edge`（翻面装订边）、`mirrored`（背面版为 true）
与 `grid`（按视图行列排列），每格给出 `origin`（原始纸格 `列,行`）、`face`（面别）、
`label`（页码，空白为 `null`）、`blank`、`rotate`（制版旋转 `0` / `180`）与 `upright`；
背面版格位已按翻转边镜像（长边左右、短边上下）。前置条件不满足时返回 `ok:false`，
错误码复用 `contour` / `thickness` / `not_single_stack` / `bad_grid`，翻面参数非法为 `bad_flip`。

`POST /api/find-path` 在方案 JSON 之外附加：

```json
{
  "target": { "cell": "1,0", "face": "back" },
  "options": { "maxDepth": 8, "timeoutMs": 2000 }
}
```

从方案全部步骤合法回放的末态出发，BFS 搜索收成单叠、且原始纸格 `cell`
（`列,行`）的 `face`（`front` / `back`）朝上为封面的最短后续折法。
命中时返回 `solved:true`、`depth` 与最多 3 条 `solutions`
（每条含 `steps`、收成格 `finalCell`、封面原格 `topPanel`、封面面别 `coverFace`）；
限步穷尽未命中返回 `solved:false, reason:"no_solution"`；
超过 `timeoutMs`（服务端硬性钳制为 ≤2000ms）返回 `reason:"limit_exceeded"`。
网格超过 4×4、前缀含非法折叠等前置问题返回 `ok:false`，错误码
`grid_too_large` / `bad_prefix` / `bad_target` / `bad_limit` / `bad_grid`。
返回的 `steps` 可直接追加到方案 `steps` 后交由 `/api/simulate` 回放验证。

`POST /api/trajectory` 在方案 JSON 之外附加：

```json
{
  "target": { "cell": "1,0", "face": "back" }
}
```

以原始纸格 `cell`（`列,行`）的面片身份从第 0 步逐步追踪其指定面
（`front` / `back`），命中时返回 `ok:true` 与时间线 `points`：
每点含 `step`、`cell`（当前所在格位）、`layer` / `depth`（叠内自上而下层序，
1 = 最上层）、`face`、`faceUp`（所选面朝上/朝下）、`upright`（正立/倒置）
与 `label`（空白为 `null`）。全部步骤合法时 `completed:true`、`interrupted:null`；
遇到首个非法步骤时保留此前全部节点，`completed:false` 且
`interrupted:{stepIndex,code,message,conflicts}` 标明中断原因（`contour` / `thickness`）。
目标原格越界或面别非法返回 `ok:false`，错误码 `bad_target`；网格非法为 `bad_grid`；
方案 JSON 非法为 `bad_plan`（HTTP 400）。该接口只读，不改变保存 / 导入格式。

`POST /api/creep-compensation` 在方案 JSON 之外附加 `paperThickness` 与 `bleed`，
返回逐叶爬移补偿：`spineAxis`（`vertical` 竖折脊 / `horizontal` 横折脊 / `none` 未折叠）、
`spineSide`（`left`/`right`/`top`/`bottom`，书脊在终叠的哪一边）、
`worldDir`（前口→书脊的世界单位方向）、`maxCompensation`、`leafCount`、
`canApply` 与 `overBleedCount`（超限面数，每叶正/反两面同时计数），以及
`leaves` 逐叶明细：`leafIndex`（0=最外叶）、`outsideCount` 外侧叶数、
`origin`/`panelId` 原始纸格、`creep` 该叶补偿量、`axis`（承载轴 `x`/`y`）、
`front`/`back` 各含 `offset`（该面印版视图的带符号横向偏移）、
`dx`/`dy`（原始纸格坐标下的面内分量；反面 dx 已按长边翻面镜像取负）与 `overBleed`。
前置条件不满足时返回 `ok:false`，错误码复用
`contour` / `thickness` / `not_single_stack` / `bad_grid`；
参数非法为 `bad_thickness` / `bad_bleed`。该接口只读；应用后由客户端把参数与
逐面偏移写入方案的 `creepCompensation` 独立字段，保存/导入/服务端载入均原样保留。

`POST /api/annotations/locate`（body 为方案 JSON，可附 `upto` 与 `annotations`）
把批注按**原始面片身份**定位到指定回放步：返回 `{ ok:true, upto, interrupted, points }`，
`points` 每条含 `id`、`cell`（原始纸格）、`at`（当前所在格位）、`face`、`severity`、
`resolved`、`layer` / `depth`（叠内自上而下层序，1=最上层）、`faceUp`（该面朝上/朝下）
与 `upright`；回放前缀含非法步骤时 `interrupted` 标明首个错误，批注按截断前状态定位。
该接口只读：批注做宽容规整，网格非法为 `bad_grid`。

`POST /api/audit`（body 同方案 JSON）对全部步骤完整重放后按印刷交付规则审计，
返回 `ok:true` 与 `verdict`（`pass` 可发布 / `fail` 需修订，存在 error 级结果即 fail）、
`summary`（`errors` / `warnings` / `infos` / `total` 各级条数）、
`stats`（`capacity` 容量、`folded` 是否单叠、`stacks` 叠层数、`leaves` 叶子数、
`labeledFaces` / `blankFaces` 已标注与空白面数）及 `findings`：每条含
`id`（`duplicate_page` / `split_stacks` / `inverted_page` / `capacity_mismatch` /
`blank_page` / `uncovered_cell` / `capacity_multiple`）、`severity`（`error` / `warning`）、
`title`、`message`（含阅读序列槽位的可读说明）、`cells`（对应原始纸格）与 `step`
（预留，当前检查均针对最终状态，为 `null`）。
方案含非法折叠时返回 `ok:false` 与首个错误（`code` / `stepIndex` / `conflicts`），
不附带任何后续检查结论；网格非法为 `bad_grid`，方案 JSON 非法为 `bad_plan`（HTTP 400）。
该接口只读，不改动方案与存档。

`POST /api/plans` 成功响应额外带 `version`（本次保存产生的不可变快照版本号）与
`savedAt`。方案存档删除（`DELETE /api/plans/:id`）时其版本目录一并删除；
`GET /api/plans` 列表每项新增 `versions`（该存档的不可变版本数）。

### 版本差异审阅接口（只读；快照仅在成功保存时追加）

`GET /api/plans/:id/versions` 返回某方案的全部不可变版本（序号升序）：

```json
{
  "ok": true, "id": "ab12cd34ef56", "latest": 3,
  "versions": [
    { "version": 1, "planId": "ab12cd34ef56", "name": "8页折帖",
      "rows": 2, "cols": 2, "steps": 1, "tags": [], "note": "",
      "annotations": 0, "openAnnotations": 0, "hasCreep": false,
      "savedAt": "…", "reason": "save", "restoredFromVersion": null }
  ]
}
```

- 摘要不含完整 `labels` / `steps`；`reason` 为 `save`（常规保存）或
  `restore`（由恢复历史版本后保存产生，此时 `restoredFromVersion` 为来源版本号）。

`GET /api/plans/:id/versions/:version` 返回单个版本的完整快照：
`{ ok, version, reason, restoredFromVersion, savedAt, plan }`，`plan` 即当时保存的
完整方案 JSON（标签 / 备注 / 批注 / 爬移补偿齐全）。版本号非正整数 → `400 bad_version`；
版本不存在 → `404 version_not_found`；方案不存在 → `404 not_found`。

`GET /api/plans/:id/diff?from=A&to=B` 以**原始纸格与步骤序号**为稳定身份比较两个版本：

```json
{
  "ok": true, "id": "…",
  "from": { "version": 1, "savedAt": "…" },
  "to":   { "version": 2, "savedAt": "…" },
  "diff": {
    "gridSize": { "from": {"rows":1,"cols":2}, "to": {"rows":2,"cols":2} },
    "geometryInterrupted": { "from": null, "to": null },
    "changes": [
      { "kind": "step", "index": 1, "op": "add",
        "from": null, "to": {"axis":"h","line":1,"dir":"d"},
        "fromText": null, "toText": "横线 1，▼ 向下折",
        "fromCells": [], "toCells": ["0,0","1,0"],
        "fromInvalid": false, "toInvalid": false,
        "cells": ["0,0","1,0"] },
      { "kind": "label", "cell": "0,0", "face": "back", "op": "add",
        "from": "", "to": "2",
        "outOfGridFrom": false, "outOfGridTo": false, "cells": ["0,0"] },
      { "kind": "annotation", "op": "change", "fields": ["severity"],
        "from": { "id": "a…", "cell": "0,0", "face": "front",
                  "severity": "error", "text": "套印偏差", "resolved": false, "step": 1 },
        "to":   { "id": "a…", "cell": "0,0", "face": "front",
                  "severity": "warning", "text": "套印偏差", "resolved": false, "step": 1 },
        "cells": ["0,0"] }
    ],
    "affectedCells": ["0,0", "1,0"],
    "summary": { "total": 3, "adds": 2, "removes": 0, "changes": 1,
                 "affectedCells": 2,
                 "byKind": {"grid":0,"meta":0,"step":1,"label":1,"annotation":1,"creep":0} }
  }
}
```

- `changes` 按 `grid → meta → step → label → annotation → creep` 稳定排序，
  每条 `op` 为 `add` / `remove` / `change`，`cells` 为关联原始纸格（供画布高亮）；
  - `grid`：网格尺寸变化，带 `from/fromCells`、`to/toCells`（两侧独有纸格）；
  - `meta`：`field` 为 `name` / `note` / `tags`（标签按集合差，纯重排不报）；
  - `step`：稳定身份是**步骤序号**（0 基 `index`），`fromCells/toCells` 为该步执行前
    移动侧（或非法步冲突侧）的原始纸格；
  - `label`：稳定身份是**原格 + 面别**，`from/to` 为页码字符串（空串=空白，
    `null`=该版本网格不含此格）；一侧越界另一侧空白的情况只在 `grid` 条报差异；
  - `annotation`：稳定身份是**批注 id**；仅创建步 `step` 变化不报差异；
  - `creep`：爬移补偿存在性 / 参数 / 逐面偏移变化，`changedCells` 列出偏移变化纸格。
- `affectedCells` 为全部条目的纸格并集，再并入“末态格位 / 叠内层序 / 面片朝向”
  经完整重放后不同的原始纸格（按先行后列排序）；
- `geometryInterrupted.from/to` 在该版本含非法折叠时给出
  `{ stepIndex, code, conflicts }`，几何比对按截断态进行，差异仍完整返回；
- `from`/`to` 非正整数 → `400 bad_version`；任一版本不存在 → `404 version_not_found`；
  方案不存在 → `404 not_found`；`id` 非法 → `400 bad_id`。接口只读，不产生快照。

快照物理存储于数据卷 `DATA_DIR`：`/app/data/<id>.json` 为当前方案，
`/app/data/<id>.versions/v000001.json …` 为不可变快照（临时文件 + rename 原子写入），
Docker Compose 命名卷 `fold-data` 同时覆盖二者，容器重建历史不丢。

### 方案存档接口（标签 / 备注 / 筛选）

`POST /api/plans`（body 为方案 JSON，可带已有 `id` 覆盖更新）除几何字段外还接受：

```json
{
  "name": "8页折帖",
  "tags": ["骑马钉", "A4"],
  "note": "首件确认"
}
```

约束与错误码（任一不满足均 **HTTP 400 整请求拒绝，不写任何文件**）：

| 错误码 | 触发条件 |
| --- | --- |
| `bad_name` | 名称 trim 后为空 |
| `name_too_long` | 名称超过 40 字符 |
| `bad_tags` | `tags` 非数组、元素非字符串或 trim 后为空 |
| `tag_forbidden` | 标签含控制字符或 `, ; |` |
| `tag_too_long` | 单个标签超过 20 字符（按 Unicode 码点） |
| `too_many_tags` | 去重后标签超过 8 个 |
| `bad_note` / `note_too_long` | 备注非字符串 / trim 后超过 500 字符 |
| `bad_annotations` / `bad_annotation` | 批注非数组 / 单条批注非对象 |
| `bad_annotation_id` / `duplicate_annotation_id` | 批注 id 格式非法 / 与其它批注重复 |
| `bad_annotation_cell` / `bad_annotation_face` | 原格坐标非法或越界 / 面别非 front·back |
| `bad_annotation_severity` / `bad_annotation_text` | 级别非 error·warning·info / 正文非字符串或为空 |
| `annotation_too_long` / `annotation_control_chars` | 正文超过 500 字符 / 含非法控制字符 |
| `bad_annotation_step` / `bad_annotation_resolved` | 创建步越界 / resolved 非布尔 |
| `too_many_annotations` | 批注超过 200 条 |
| `bad_plan` | 几何字段（rows/cols/labels/steps）非法 |

成功时返回 `{ ok:true, id, plan }`，`plan` 含规范化后的 `tags` / `note` 与
`createdAt` / `updatedAt`（覆盖更新保留 `createdAt`、刷新 `updatedAt`）。
写入采用临时文件 + rename 原子替换，非法请求不会留下半截文件。

`GET /api/plans` 返回存档列表，查询参数：

- `tags`：**标签交集**，逗号（或分号）分隔，如 `?tags=骑马钉,A4`，方案须含全部标签；
- `q`：名称关键词，大小写不敏感子串匹配；
- `since`：仅返回此时间之后更新的存档，接受 ISO 字符串或毫秒数（非法返回
  `400 bad_since`；标签参数含非法字符返回 `400 bad_tag_filter`）。

响应：

```json
{
  "total": 12,
  "matched": 3,
  "items": [
    { "id": "ab12cd34ef56", "name": "骑马钉样册", "rows": 2, "cols": 2,
      "steps": 2, "tags": ["骑马钉", "A4"], "note": "一版",
      "annotations": 3, "openAnnotations": 1,
      "createdAt": "…", "updatedAt": "…" }
  ],
  "allTags": [{ "tag": "骑马钉", "count": 5 }]
}
```

- `total` 为全部存档数（不受筛选影响），`matched` 为筛选命中数；
- 排序为 `updatedAt` 倒序，时间相同按 `id` 升序（稳定）；
- `allTags` 为全部存档的标签聚合（不受筛选影响），按出现次数倒序、同次数按标签升序。

`GET /api/plans/:id` 返回完整方案 JSON（含 `tags` / `note`）；
`DELETE /api/plans/:id` 删除存档。缺少 `tags` / `note` / 时间戳的旧版存档可正常列出，
首次保存更新时自动补齐。
